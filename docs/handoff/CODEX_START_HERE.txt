Build an offline-first installed desktop app: Tauri2/Rust + React/TypeScript + bundled Python analysis. Default action: Prepare & watch. Begin live capture before arming; obtain identity and full parameter evidence while disarmed; create persistent armed-interval IDs automatically; continue short-lived radio capture; collect/reconcile BIN/TLOG/params after disarm. Preserve native Mission Planner and QGC logs as complementary evidence to the app-owned recorder.

Add Network & devices: OS-specific interface/route/firewall/socket/stream diagnostics and concrete reviewed repairs with narrow privileges, verification and rollback. For the Q22 dual-network topology preserve Internet routing, set the correct drone-interface address and receiver destination; do not bridge/NAT or disable the firewall. Repairs must not disrupt armed or unknown-state aircraft links. MP's MinGW/H265 runtime profile and QGC's own runtime require separate adapters.

Critical protocol constraints: QGC MAVLink forwarding is one-way. Automatic parameter/log requests need a tested bidirectional path. Any router must preserve control traffic/failsafe behavior and never keep a dead GCS alive by sending substitute heartbeats. Parameter downloads are not atomic; capture completeness is distinct from flight-time applicability. Full pre/post readback plus observed changes and matched BIN evidence form the configuration timeline.

Never link by filename/date/sysid alone. Files and flights are many-to-many with source spans. Ask for an exact SD filename only when a listing or validated mapping established it; otherwise scan the chosen SD folder and verify contents. Unknown, partial and conflicting evidence must remain visible. No workflow can guarantee recovery of data that was never recorded; the enforceable requirement is no silent wrong association or false completeness.

Connect every eligible metric to its effective parameter interval, firmware/hardware and comparable conditions. Preserve original and FACt-based baselines with legacy aliases and original bytes. Do not claim PID changes caused endurance gains from current data alone. Proposed numerical tuning remains firmware/evidence gated; aircraft parameter writes and flight commands are outside this release.

Use the revised milestones and acceptance cases. Convert the design JSON into validated runtime schemas and executable tests. Example JSON files are illustrative contracts, never real flight evidence or permissions to change this computer. Pin external source versions and validate actual OS/GCS/radio/firmware behavior. No hardware testing has been performed by this handoff.

Deliver usable vertical slices and report what works, tested evidence and remaining gaps. Do not call a mock dashboard complete.
