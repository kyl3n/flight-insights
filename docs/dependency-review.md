# Dependency review — log ingestion follow-up

This records inspected package metadata and license texts in the managed Linux
environment on 5 October 2026. It is not a completed review of every Windows,
macOS or Linux binary shipped in an installer. Lockfiles identify resolutions;
the actual frozen payload determines which code and notices are distributed.

## pymavlink scope must follow the collected modules

The installed `pymavlink-2.4.49.dist-info/licenses/COPYING` starts with an exception
for **generator output**, then supplies LGPLv3. It does not establish that every
file in the Python distribution is MIT licensed. The inspected headers state:

| File | Observed status |
| --- | --- |
| `pymavlink/dialects/v20/ardupilotmega.py` | Identifies itself as generated by `mavgen.py`; generated-output exception applies to the described output, with its MIT notice |
| `pymavlink/mavutil.py` | “Released under GNU LGPL version 3 or later” |
| `pymavlink/DFReader.py` | “Released under GNU GPL version 3 or later” |
| `pymavlink/generator/mavgen.py` | “Released under GNU GPL version 3 or later” |

The implementation uses a generated dialect for its scoped TLOG adapter and a
project implementation for the DataFlash path; no DFReader/WebTools source reuse
is assumed approved by installing a package. Confirm this against the final
PyInstaller module/archive inventory. Static and dynamic import collection can
pull in additional helpers. An upstream reader used only to validate fixtures is
distinct from including that reader in the installed runtime.

If the shipped runtime contains only the relevant generated output, retain its
complete MIT exception/copyright text. If LGPL-covered helpers are collected,
provide the applicable notices and license texts and a practical compliant means
to modify and recombine/replace that library with the application. In particular,
a single frozen executable is not automatically a replaceable shared-library
mechanism. LGPLv3 section 4 addresses notices, GPL/LGPL texts and recombination or
replacement, with installation information where applicable. If GPL-covered code
is collected or copied, assess the resulting distribution's GPL obligations;
the generated-output exception cannot be used for unrelated helper code.

Record the selected redistribution method and verify it using the exact source,
build instructions and artifact that are supplied. Do not claim compliance solely
because a source repository exists or because PyInstaller itself has an exception.

## Native and transitive notices

Apache Arrow's installed `LICENSE.txt` and `NOTICE.txt` contain attributions for
included projects in addition to the Apache license. Preserve them intact and
inventory the native libraries actually collected for each architecture. A
PyArrow wheel can contain Arrow/Parquet libraries and codec/support dependencies;
the Python package's top-level license is not a substitute for their notices.

The installed fastcrc wheel also supplies
`fastcrc-0.5.0.dist-info/sboms/fastcrc.cyclonedx.json`. Its CycloneDX 1.5 inventory
lists Rust dependencies: most declare MIT OR Apache-2.0; generic-array and spin
declare MIT; unicode-ident 1.0.24 additionally declares Unicode-3.0. Preserve this
inventory and resolve the applicable transitive notices if the native accelerator
is shipped. The root fastcrc MIT file alone does not document all those components.
The release packager excludes fastcrc and rejects its presence in the frozen
inventory. It uses the generated dialect's pure-Python CRC fallback, exercised by
the frozen TLOG smoke check. fastcrc remains an installed build/test dependency;
its installation alone does not make it part of the shipped runtime.

lxml's installed `LICENSES.txt` identifies ElementTree/CPython-derived code and
resources with additional terms. Its binary-wheel section names zlib (zlib
license), iconv (LGPL-2.1), and libxml2/libxslt/libexslt (MIT notices). If the frozen
payload includes lxml or these native libraries, retain the applicable texts and
resolve the bundled iconv redistribution/relinking requirements. Do not classify
the complete lxml wheel as BSD-only. Optional test/resources that are not shipped
should not be reported as runtime components; prove their absence in the payload.

The packaged Python runtime and standard library, Rust crates, system webviews and
platform runtime libraries have their own terms. Use each target's actual
inventory. A Linux system library dependency and a copied library embedded in an
AppImage are different distribution situations. The Windows offline WebView2
installer also has its own redistribution conditions.

`scripts/package-engine.py` now collects the installed PyArrow LICENSE/NOTICE,
pymavlink COPYING, psutil, PyInstaller and CPython texts. It produces a
per-target frozen Python/native-entry inventory with hashes and rejects collected
DFReader, mavutil, generator, lxml, iconv and fastcrc components. Linux packaging also
collects available owning-package copyright texts and common license texts for
copied system libraries. These are release controls, not evidence that an as-yet
unbuilt target passed them. Check the actual generated inventory and notices;
front-end/Rust dependencies and target-specific native components still require
their applicable attribution and redistribution review.

## Release evidence to produce

For each final installer, retain:

1. Its SHA-256, source commit and locked dependency resolutions; an inventory of
   frozen Python modules, native libraries, Rust dependencies and frontend code.
2. Complete applicable license and NOTICE files, accessible with the delivered
   artifact; include required copyright and modification notices.
3. A record of any LGPL/GPL-covered payload, its corresponding source/version,
   chosen distribution method and tested replacement/rebuild instructions where
   required. Resolve this before distributing that compiled payload.
4. License and provenance for redistributed reference logs, parameter files,
   icons and other assets. Real flight evidence is not automatically public data.
5. The project owner's chosen application license/distribution terms. Third-party
   notices do not select the license for Q22's original source.

No ArduPilot WebTools, FilterReview or PIDReview source has been copied in this
reviewed work. Future reuse needs its own license decision and numerical parity
evidence. No complete transitive release audit or legal sign-off is claimed here.
See [release-qualification.md](release-qualification.md) for the artifact-bound
platform and hardware acceptance procedure.
